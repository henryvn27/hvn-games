# HVN games design direction

## Design read

This is an experience surface for friends choosing a browser game together. The page should feel like a small game concourse: the playable artifact is the sign, the interface is the departure board, and every label helps someone decide whether to press play.

## Visual world

Split-flap departure board translated into an arcade shelf. Use fixed rows, restrained rules, condensed data labels, and one live playfield as the visual authority. The gallery stays quiet around the game so the real runtime can carry the personality.

## First viewport

The first viewport leads with the featured game name, a concrete rule, a direct Play action, and the actual Phasebound runtime in attract mode. It must be obvious that the preview is live gameplay, not a screenshot or decorative canvas.

## Motion grammar

One live attract loop and small state changes that feel like a board updating. No blanket entrance animations, no ambient glow fields, and no motion that hides content. Reduced motion freezes the attract frame while keeping the game route available.

## Material and type

Cool paper and ink in light mode, near-black board surfaces in dark mode, with a single teal page accent. Phasebound may use cyan, amber, and red as game-state colors. Use installed sans typography for display and monospace only for commands, measurements, and board labels.

## Boundaries

- Keep the current public Pages and shared repository flow.
- Keep the real Phaser runtime in the gallery preview.
- Keep local-only play intelligence transparent, resettable, and free of third-party tracking.
- Do not copy Poki or Notch branding, assets, layout, wording, or claims.
- Do not add fake catalog depth, invented popularity, empty icons, or generic marketing sections.

## Quality bar

The page must make a friend want to play within seconds, work at desktop and narrow mobile widths, respect light and dark preference, expose keyboard and touch paths, and show the game doing its job before explaining it.
